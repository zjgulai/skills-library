## 3. 第二起工具缺陷：备份被"逐操作"覆盖（已修＋已重建）

同一个文件有多处操作时，执行器**每处都写一次备份** ⇒ 备份只剩"最后一个操作前"的状态。
实测：`goals` 的备份里已经有 3 个标题（应有 0 个）。

- **修**：备份只在**首次碰到该文件**时写（`backedUp` 集合），带用例
  （"同一文件两处编辑，备份必须是改前原件"）；
- **重建**：真原件 = 把计划里的插入**逐条取反**（`split(find).join(replace)` 的精确逆运算）；
  并与"半成品备份去掉标题"的结果**交叉验证一致**后才写回备份目录，附 `backup-repair-note.json`；
- **回执现在是两份**（工具上一轮已改成按计划名命名）：
  `library-backup-sections-2026-09-28/text-plan-sections-2026-09-28-receipt.json` 与 `backup-repair-note.json`。

> 与 55 号 §10 那起（回执被覆盖）是同一类问题的两个面：**"每轮同名/每次重写"在单计划、单操作时看不出来，
> 一遇到多计划或多操作就发作**。两处现在都有用例兜住。
