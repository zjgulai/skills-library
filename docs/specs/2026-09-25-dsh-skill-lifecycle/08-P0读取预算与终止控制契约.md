# 08｜P0 控制契约：读取隔离、累计预算与终止恢复

状态：首版工具边界A已确认，T01—T08已完成本地实现，共275项测试通过（T06原生模块级、T07执行前门、T08窄服务图真实会话），见[17-T08记录](17-T08实现与验证记录.md)；真实provider探针（T09）仍未执行。生产岗位、权限、应用bundle、用户DSH主目录和模型调用均未授权变更或执行。

前置资料：[07-P0原生执行接缝与隔离方案](07-P0原生执行接缝与隔离方案.md)、[03-DSH运行与验收契约](03-DSH运行与验收契约.md)。本轮静态证据摘要：[p0-control-seams.json](evidence/p0-control-seams.json)。本文件定义实现应满足的契约，不承诺仅靠某个hook就已覆盖所有入口。

## 1. 本阶段要交付什么

只建立一个可以安全执行 `validate-data` 本地报告／小型表格任务的专用测试作用域。保留原版业务输入输出；原版和候选使用相同工具与权限。先证明控制逻辑和原生集成，再开展获准的小批模型探针。

不在P0建设多租户平台、远程集群、跨平台适配、动态任意工具编排或自动生产发布。不新增六个常驻Agent。把职责分成三个可测试接缝即可：操作准入、请求准入与用量结算、工作流终止与恢复。

## 2. 威胁模型与限制

需要防止：被测模型受用户输入、Skill、报告或工具结果诱导，读取金标／其他运行文件、修改原版或裁判、发出额外网络请求、超出预算或在停止后继续执行。

假设宿主和加载的控制代码已经审查且可信。本方案不宣称抵御恶意宿主插件、本机其他高权限进程或系统被攻破。只分会话或给目录起名不构成访问隔离；同一操作系统用户运行的恶意任意代码也不能靠应用层路径过滤可靠约束。

首版已选A：不向被测执行者开放通用shell、任意代码执行、浏览器、网络MCP、子代理和可更换工具装配的能力。它可以读允许的本地文件、做受控计算、将报告写入允许的产物区。这个收缩必须同时应用于原版与候选，结果只对该环境有效，不能直接推广到日常全工具岗位。

如果业务必须执行任意Python或SQL程序，应另行验证真正的进程／文件／网络隔离后再开放，不能用命令黑名单或“禁止open”的字符串检查冒充沙箱。无需改变 `validate-data` 的任务职责来迎合控制器。

## 3. 文件和工具准入契约

### 3.1 访问矩阵

以下区域是逻辑分区，路径在实现时由宿主解析和绑定，不允许模型任意指定运行根。

| 区域 | 被测执行者 | 优化者 | 裁判／核对流程 |
|---|---|---|---|
| 原始源库 | 不直接访问，读取本轮冻结副本 | 只读允许的源副本 | 读取身份清单，不修改 |
| 本轮Skill与允许参考副本 | 只读 | 在开发候选区读写，不改冻结版本 | 只读 |
| 当前题目输入 | 只读，不含金标 | 仅开发输入与获准反馈 | 按职责只读 |
| 本次运行产物区 | 可创建／更新允许的报告与计算结果 | 不改已封存被测输出 | 只读，评分另写 |
| 金标、终测答案、评分规则 | 不可读写 | 不可读写受保护内容 | 仅受控裁判可读；运行期间不得修改 |
| 其他运行、其他会话、凭据、用户目录 | 不可访问 | 无默认权限 | 无默认权限 |
| 状态与预算账本 | 不可写，必要时仅给摘要 | 不可改 | 由可信控制层写入 |

矩阵不能只写在SKILL.md，必须由工具／文件后端及受控执行通道实施。标注“不可访问”是目标要求，不表示现有DSH已经做到。

工具之外也要核对上下文入口：继承会话、全局记忆、项目规则、启动hook、额外skill provider、文件搜索补全和自动附件均可能把受保护内容送进模型。专用测试装配应只注入冻结且获准的材料；正常会话的个人记忆不应默认进入被测运行。禁止读取金标却把它提前注入上下文，仍然属于泄漏。

### 3.2 操作准入规则

- 每个调用必须关联有效的运行标识、会话、角色和配置版本；只管理专用测试作用域，不影响其他会话。
- 使用精确工具标识白名单。未知工具、未知路径参数或未识别操作默认拒绝；列表、搜索、附件读取和Skill资源读取同样要纳入范围。
- 读取前按真实路径、文件类型和允许根核验；不使用简单字符串前缀。拒绝指向范围外的软链接、设备、管道与未授权别名。
- 输入与冻结Skill根不可被执行者修改；输出根由宿主预置，不能与源、金标或其他运行重叠。创建新文件时验证真实父目录，且防止借链接改写受保护文件。
- 如果开放任何能自行访问文件的执行器，路径门禁必须覆盖该执行器；无法覆盖则不开放。对可变链接的竞争条件要通过受控目录所有权及实际I/O边界验证处理，不能仅“检查后相信路径不变”。
- 拒绝后不允许自动升级为询问授权并在本运行放宽；需要更多能力时结束为受阻，提出新的、明确的运行配置版本。
- 读取限制还包括返回内容：不把不必要的目录清单、配置、跨会话信息或原始日志泄漏给执行者。

### 3.3 受控计算与公平比较

首轮表格以普通文本／CSV输入为主。若需要工具复算，优先使用无任意代码执行、无外部I/O的计算接口：宿主提供当前允许数据，模型只指定通用聚合或算术操作，结果记录实际输入和运算。不是为特定题目写正确答案函数，也不把所有需要判断的规则硬编码。

通用计算范围、数据类型和工具标识必须在运行前冻结，并原样提供给无Skill、原版和候选。T03已实现有限CSV、标量与聚合纯函数并完成本地链路测试，见[12-T03](12-T03实现与验证记录.md)；尚未接入DSH工具准入。首次验证仍应标“受限工具配置”，进入真实代表岗位回归时重新测量。

## 4. 累计预算契约

### 4.1 三个计数不能混为一谈

- **任务执行**：一个测试输入在一套配置下的完整Agent任务。
- **模型请求尝试**：每一次真实provider发送，包括失败、重试、压缩、裁判和其他模型调用；不等于对话轮数。
- **使用量与时间**：输入／输出／缓存等provider实际用量，以及单次、任务和批次墙钟期限。

本阶段不钉死金额或次数；真实探针前由用户批准明确的数值上限。未知用量不能按0计入；取消不保证退款；没有价格版本和请求上界不能承诺精确费用硬上限。

### 4.2 准入、预留、结算

1. 请求进入实际发送边界前，检查运行仍可执行、授权与期限有效、剩余额度足够；记录唯一尝试标识并预留本次额度。
2. 首版限制单一在途请求，减少并发超额与归属复杂性；后续需要并发再扩展。
3. 每个重试是新尝试，也必须准入和计数。只拦Agent外层一步而看不到provider内部重试，不能声称覆盖真实请求预算。
4. 请求结束按可核验用量结算，重复事件按尝试身份去重；不能把流式快照与最终汇总重复相加。
5. 发送后发生中断、缺结果或账本恢复时，预留标为待核对，不直接释放或重新发送；无法判定的费用保守保留并阻止新增调用，直到核对或新授权。
6. 账本写入失败时不继续发新请求。日志或报告可重建，已发生请求与预算不能靠模型重新描述补造。

只有能够约束完整请求输入大小、最大输出、计费口径和重试，才能提供有依据的用量上界。否则提供“请求尝试数硬限＋已观测用量／时间软阈值”，并明确超限不确定性；若用户要求费用硬限但无法保证，就阻断而非隐去差别。

### 4.3 控制层范围

启动前审计测试作用域里所有可能调用模型的组件。主任务、标题生成、上下文压缩、裁判、优化者、工具内调用与重试必须纳入总预算，或明确不启用相应组件。不得为了漏算的后台调用宣称预算达标。具体原生拦截位置须由代码核验和无模型传输桩证明。

## 5. 终止与恢复契约

### 5.1 终止不是一个cancel按钮

生命周期：`prepared → running → stopping → stopped`。正常任务结束可以是`completed`；若不能证明停止完成，保留`stop_unconfirmed`，它不是终止成功或可复用结果。

一旦进入stopping，本次运行不再返回running。重启进程、收到迟到事件或重新连接都不能自动解锁。需要恢复业务执行时，以新的获准尝试继承原批次身份与累计预算，不从零计费。

### 5.2 顺序

1. 先在持久状态中关闭新prompt、工具和provider请求准入。
2. 再撤销本测试会话的排队工作并发出在途取消；只操作本控制器拥有的会话，不清理用户其他任务。
3. 停止本次受控执行器和输出写入，等待原生空闲／终止与在途记录收敛。
4. 保存最终已知用量、产物身份、停止原因和未决事项，才标stopped。
5. 超时仍不能确认时标stop_unconfirmed并隔离本次结果，不启动下一批；不强杀整个Desktop作为默认兜底。

取消请求返回accepted，只说明请求收到了，不证明工具子进程、provider计费或inbox全部结束。迟到结果可作费用／审计核对，但不能将已停止的任务自动改成业务通过。

### 5.3 恢复

控制层只能恢复身份匹配且已提交的阶段。校验源、候选、测试、裁判、环境和政策版本；不匹配则让受影响阶段失效，保留历史记录。运行所有权用唯一标识与受控锁保证，同一运行不能有两个恢复者同时推进。

重点演练三个窗口：请求预留后未确定是否发送；模型完成但用量未提交；产物写完但阶段状态未提交。前两种先核对，后一种验证产物后重建报告，不能简单全量重跑。

## 6. 证据契约

每项控制决定最少记录：运行／任务／尝试身份、角色、内容与环境身份、操作类别、允许／拒绝、理由、事件序号／时间、预算预留或结算状态。路径默认使用项目相对引用，秘密与金标不进入通用报告。

证据分为：静态代码事实、无模型控制测试、真实DSH工具／会话验证、获准provider请求。四类分别标记，不用模拟轨迹填真实结果。模型产生的“我没有读金标”不算隔离证据。

## 7. 无模型验证清单

所有输入均为公开构造物或无敏感哨兵；没有真实金标、用户文件或付费请求。

| ID | 行为 | 预期 |
|---|---|---|
| C01 | 读取允许的输入与冻结Skill | 成功，记录内容身份 |
| C02 | 读取输入根外哨兵、父路径或链接目标 | 拒绝，不返回内容 |
| C03 | 写本次输出；写源／裁判／其他运行 | 前者允许，后者拒绝 |
| C04 | 搜索、列目录、附件或未知工具访问未授权范围 | 拒绝或不装配，不能旁路 |
| C05 | 请求通用shell、网络、子代理或动态插件 | 首版拒绝，日志能定位 |
| C06 | 两个执行者争用同一剩余额度 | 准入不超额；首版只允许一个在途 |
| C07 | provider在同一步内部重试 | 每次尝试都计数，额度用完不发送 |
| C08 | 用量缺失、重复或迟到 | 不按0、不重复结算、不自动解锁 |
| C09 | 账本不可写或版本不匹配 | 请求发送前阻断 |
| C10 | stop到达时已有inbox和在途工具 | 先关准入，再清本会话队列并取消 |
| C11 | stop后重连、新prompt或迟到结果 | 不重新执行；结果仅审计或核对 |
| C12 | 停止无法确认 | stop_unconfirmed，不标通过、不启动下一批 |
| C13 | 三种恢复窗口 | 不重复发送、不重置预算，身份不符拒绝复用 |
| C14 | 非测试岗位操作 | 控制器不改变其模型、权限或队列 |

无模型测试通过仍不能证明真实provider完整用量或取消行为；这些留给之后获准的小批探针。检查数量不是质量分数，任一关键边界失败就不能进入相应真实实验。

## 9. 本轮核验的原生接缝

共同前缀：`/Applications/DSH Desktop.app/Contents/Resources/app/node_modules/@deepseek-ai/`。

| 控制 | 文件定位 | 已确认事实 | 必须补的验证 |
|---|---|---|---|
| 单调拒绝 | `dsh-tools/lib/index.js:2807–2829` | `tools.guard`返回原因字符串可拒绝，agent.ctx范围的guard只作用于相应Agent，其他guard不能强行放过已拒调用 | 宿主插件装配时机、实际工具路径覆盖、内部服务直读与上下文入口 |
| 调用载荷 | 同文件 `:3030–3059` | 执行含name、agent及深冻结的参数快照 | 参数校验到实际I/O之间的路径竞争和别名 |
| 审批后仍拦截 | 同文件 `:3115–3147` | pre-execute/ask完成后，allow仍经过guardReason | 普通waterfall的顺序不用于作不可覆写保证；应使用monotonic guard |
| 模型请求包装 | `dsh-llm/lib/index.js:2303–2307` | `streamWithRegistration`汇入 `llm/stream` 后调用adapterStream；prepared路径也汇入此链（同文件约:2168） | 当前provider内部重试是否一一对应wire请求仍未知，不能宣称硬费用限额 |
| Agent重试 | `dsh-agent-loop/lib/index.js:1016–1036,1088–1098` | 每次attempt重新prepare和stream；pre-step不覆盖所有重试次数 | 所有附属模型调用是否进入同一受控账本，完整归属待验证 |
| 用量边界 | 同文件 `:1048–1074,1108–1114` | 成功或部分中断可能带usage，失败记录可能没有 | 缺失、重复、迟到事件不可当0或重复计数 |
| 清队列取消 | 同文件 `:798–803` | 原生agent.cancel不保留inbox时会clear并abort | 是插件内部句柄接缝；外部sessionController.cancel仍保留队列，不能混用语义 |
| 等待空闲 | 同文件 `:853–857` | `whenIdle()`等待活动句柄稳定结束 | 协作取消不是强杀；在途工具、隐含子任务与provider计费须分别确认 |
| macOS shell策略 | `dsh-sandbox-local/lib/index.js:65–74` | 策略为allow default再限制file-write，未提供本次要求的读取白名单 | 不开放通用shell或另行提供真实读隔离，不能靠cwd解决 |

因此推荐实现接缝是专用作用域的 `tools.guard`、受控 `llm/stream` 请求包装、原生agent清队列取消／whenIdle，加外层持久化准入状态。不是改写整个Agent loop，也不是只依赖软提示。

上表中标注"必须补的验证"的接缝，T06已在裸cordis上下文中用真实ToolRuntime/LlmRuntime实测：作用域guard单调（pre-execute的allow不能覆写拒绝）、白名单工具真实执行、两条stream路径都经过受控包装、每次重试独立预留、离线adapter零网络。实测结论与偏差见[15-T06记录](15-T06实现与验证记录.md)；该表保留为静态调查的历史记录，不再作为当前证据。

`tools.guard`是同步接口，适合检查角色、状态、已核对的参数和精确工具身份；异步真实路径校验、文件打开和大小限制必须在可信I/O实现边界完成。不能把异步检查塞进同步guard后假定已经拒绝，也不能忽略校验与实际打开之间的竞争条件。若宿主启用 `run_code` 等程序化工具调用传输，还须核对最终能力是否经过同一guard、是否允许额外代码I/O；未验证前不装配这类模式，不猜测可用restrict参数。

`llm/stream`是可扩展waterfall，不是已证明不可覆写的预算安全门。专用装配要冻结处理器顺序，确认所有实际发送均经过计数，不能由其他middleware直接调用adapter旁路。无法做到时只能标部分覆盖并阻断对应硬预算声明。

## 10. 最小实现边界

- 首版已确认A：无通用shell、无任意代码、无网络MCP／浏览器／子代理；原版与候选同配置，受限环境结论不能外推全工具岗位。
- 控制代码通过可维护插件／测试装配接入，不修改app bundle；新测试岗位与配置写入必须显式批准。
- 当前provider内部重试和辅助模型调用的边界，在实现时用无网络传输桩核对；找不到足够接缝时不得声称费用硬上限。
- 真实模型、次数、输出上限、墙钟和预算数值，在S4前确认；S0—S3不调用付费模型也不代表无需审批配置变更。
