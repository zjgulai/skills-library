## 1. 交付物

`control/governance-ledger.mjs`：append-only 处置账本。`openGovernanceLedger({ root, now })` → `{ path, append, read, latestFor, historyFor, verify }`，落盘为 `<root>/governance/dispositions.jsonl`（一行一条记录）。

**记录形状**（计划里的六字段＋三个机制字段）：

| 字段 | 含义 |
|---|---|
| `record_type` | 固定 `governance_disposition` |
| `skillId` / `version` | 处置对象身份（版本是内容身份，如 `original-1e424822`） |
| `disposition` | `promote`／`retain`／`retire`／`merge`／`rollback` |
| `evidenceRefs` | **指针**（文档名＋小节），不复制内容 |
| `sourceDigests` | 处置所依据的内容摘要（64 位十六进制） |
| `previous` | 该链的**父记录 id**；首条为 `null` |
| `dispositionId` | 记录的封存 id |
| `decidedAt` | 决定时间（epoch ms，可回填历史日期） |

**三件"不可覆盖"的机制**：

1. **比较交换式追加**：`append` 必须显式给 `previous`（首条给 `null`），模块不自动补血缘。写前**重新从磁盘读链头**，与传入的 `previous` 不一致即 `CHAIN_CONFLICT: expected <链头 id>`——"改写既有决定"在任何调用姿势下都过不去。
2. **同一决定只出现一次**：`dispositionId` 是键排序规范形的 sha256，重复提交同一条即 `DUPLICATE_DISPOSITION`。审计者可从盘上那一行**独立重算**这个 id。
3. **只能追加后续处置**：对同一 `(skillId, version)` 再下决定，必须以上一条的 id 作 `previous`——旧记录原样保留、按序可读，新记录成为链头。物理上走 `appendFile`（测试断言"新增一条后旧字节不变、行数 +1"）。

**读取一律 fail-closed**：`verify`/`latestFor`/`historyFor` 都先回放整份账本，任一异常即拒答，不返回"能读到的那部分"：

- `LEDGER_TAMPERED: line N`——该行内容与封存 id 不符（**先比内容、再判语义**：改写过的行不会被当成"字段写错的记录"）；
- `CHAIN_FORK: <skill>@<version>`——同一条链上两条记录认了同一个父（**根 `null` 也算父**）；
- `CHAIN_BROKEN: <skill>@<version>`——记录的 `previous` 指向本链从未有过的 id（如中间行被删）；
- `INVALID_RECORD: line N`——不是处置记录（含外来记录类型、缺字段、id 形状不对）；
- `DUPLICATE_DISPOSITION: line N`——同一条决定出现两次。

**边界**（照计划）：账本只存事实与指针，不存内容——`evidenceRefs` 单条 ≤500 字符、≤32 条，`sourceDigests` 必须全是真摘要，字段集严格（多一个键即拒）。**候选的评审结论不进本账本**：账本记的是"技能版本"的处置，候选自己的落档在 `candidates/<id>.disposition.json`；`promote` 才表示某版本被启用。

**已登记的残余窗口**：`append` 的"读链头 → 追加"之间是毫秒级 TOCTOU 窗口，本账本按**单写者**使用。窗口内并发追加会在链上留下分叉，但**不是静默损坏**——`verify` 报 `CHAIN_FORK`，账本随即停止作答。不引入锁文件是为了不复制 `run-state` 的锁与陈旧锁处置逻辑。

## 3. 过程中发现的问题

- **冻结输出被测试当场抓住**：`verify()` 返回的是 `freeze` 过的对象，测试里 `report.skills.sort()` 直接抛 `TypeError`（只能读不能写）。这是模块行为正确、测试写法要改（`[...report.skills].sort()`）。
- **分叉判定第一版写错**：只认"父必须是链上记录的 id"，于是"两条记录都认根 `null`"被判成 `CHAIN_BROKEN` 而不是 `CHAIN_FORK`。修法是把父记录成集合（根也算父），测试用例就是这条的回归装置。
- **变异实验不要混用编辑手段**：本轮有一处变异用 `python3 - <<PY` 回填，替换串没匹配上（`str.replace` 静默无操作），文件停在半改状态、红得不明不白。变异一律用 Edit 工具逐处改、逐处复原。
