# 25｜判者反向探针与校准集（2026-09-27）

用户 2026-09-27 选择「先做独立盲判」后的第①项：**判者反向探针＋校准集**。纯工程 + 一次真实盲判派发，**零新增真实请求**。

## 1. 要解决的问题

24 号记录第 4 节第 5 条写得很直白：**判者质量本身需要被验收**——10/10 与机械门一致，也可能来自"只会同意"的判者。本步把判者变成被验收对象。

## 2. 机制（`control/blind-packet.mjs` 扩展）

- **探针混入**：`buildPacket({ …, probes })` 把带**预钉 expectedGate** 的合成产物与真实产物**同形混排**（同一 seed 洗牌、同样的字段），判者无法从结构上分辨。探针只登记在**键文件**里（`slot.probe=true, expectedGate, label`）。
- **校准**：`calibrate({key, scores})` 比对每条探针的 `expectedGate` 与判者的 `gate` → `calibrated`／`miscalibrated`，并列出不一致的 `label:slot`；**没有探针的包直接 `NO_PROBES`**（不许"空集校准"）。
- **门后有门**：`certifyRound({calibration, verdict})`——判者未过校准，轮次结论**一律降级为 `inconclusive`**，理由分别是 `JUDGE_MISCALIBRATED`（判错探针）或 `JUDGE_UNCALIBRATED`（这个包根本没探针）。**accept 只有在"三条停止条件成立 **且** 判者已校准"时才成立。**
- **盲包不再携带 seed**（改前它会外泄：seed 文本能被 `leaks` 命中，且seed 可用于重算 slot 顺序）；泄漏检查改为精确 token + 探针标签。
- **一轮一文件**：轮次记录改名为 `round-<n>-blind-<packetId>.json` 并加覆盖保护——此前两次盲判都写 `round-1-blind.json`，前一版被覆盖（已按 packetId 重写两版记录，见第 4 节）。

测试：`tests/judge-calibration.test.mjs` 10 项（探针不改变盲包形状、不泄漏探针身份、解盲跳过探针、全对=calibrated、**只会说 true 的判者被负探针抓住**、**只会说 false 的判者被正探针抓住**、无探针包报 `NO_PROBES`、误判→`JUDGE_MISCALIBRATED` 降级、无探针→`JUDGE_UNCALIBRATED` 降级、探针摘要参与 packetDigest）。

| label | 期望 | 内容要点 |

## 4. 本轮暴露并修掉的三件事（连带）

1. **记录覆盖**：两次盲判同写 `round-1-blind.json`，前一版被覆盖 → 改为按 packetId 命名 + 覆盖保护；两版记录现在都在：`round-1-blind-packet-5cc1b395e689c30d.json`（无探针那轮）与 `…-f7fdfd56cf3429c2.json`（带探针这轮）。
2. **旧盲判的定性**：无探针那轮在新门下**不能认证**，其记录现为 `inconclusive / JUDGE_UNCALIBRATED`（**原始指标仍保留：targetHits 3/3**）。这不是说那轮判错了，而是说它无法被认证——两者必须分清。
3. **一处间歇红被定位并修掉**（非本轮功能）：`budget-ledger` 的两条"在途尝试"测试用真实时钟，而 fixture 的 `attemptTimeoutMs` 只有 100ms，全量并行跑时两次 reserve 之间超过 100ms 会把在途判成过期（`reconcileExpiredAttempt` 的设计行为）→ 断言从 `ATTEMPT_IN_FLIGHT` 变 `UNRESOLVED_USAGE`。修法是**测试注入固定时钟**，产品未动；修后全量连跑三次全绿。
