## 2. 载体与接线（`tests/w2-ab-comparison.test.mjs`）

- 分臂技能根：每次运行把该臂的技能文本复制到 `<run>/skill-root/validate-data/SKILL.md`，复制后**再验一次摘要**（`the armed skill identity must survive the copy`），并同时校验另一臂的源未被触碰（候选臂运行时冻结原版必须仍是 `1e4248…`）。
- 候选臂额外硬门：`candidate.json` 必须 `sealed:true`、候选文件摘要必须等于登记值（未封存或摘要漂移一律拒绝）。
- 每次任务：独立 run 目录、干净会话、独立输出区；审计含 `tool_admitted(skill)` 留痕；记录含 `arm`／`candidate_id`／`skill_digest`。
- **本轮修掉一个静默故障**：窄图里发出的用户消息用 `createUserMessage({content})` 而未带 `source`；一旦挂上 `dsh-tool-skill`，其 `pre-step` 会在 `catalogMessage()` 读 `message.source.kind` 时抛错，而 agent-loop 的 `kick()` 把回合异常吞掉——表现为"回合正常结束、零模型请求、零产物"。定位方式：在插件之前注册一个外层 `agent/pre-step` 包装器打印异常。修法：`createUserMessage({ content, source: { kind: 'user' } })`。（A4 载体未挂 tool-skill，故此前未暴露；A4/T09 的历史读数不受影响。）

## 4. 判定与结论（可声明 / 不可声明）

- **可声明**：在本批（各题 1 次、单模型单路由 `vod/gemini-3.8-flash`、原生加载）下，候选 `t7-boundary-001` 让 t7 从"未界定范围"变为"明确界定并声明不套用核验格式"，同时把该题尝试数从 6 降到 2、tokens 从 27.9k 降到 6.1k；两道回归题未观察到退化。
- **不可声明**：样本量 1（每臂每題 1 次），t7 的行为差异可能来自采样波动；不构成成功率、误报率或稳定性结论；未测其他题型与其他模型；候选只在"受限核验环境 + 原生技能加载"下被测过。
- **仍未覆盖**：独立盲判（本轮仍是主代理判）、终测集与答案隔离、候选在多轮迭代下的表现。

**读数解读（比单次更重要的两点）**：
1. **行为差异稳定**：候选组 3/3 都在回答开头界定"这不是核验请求、超出核验范围、不套用 Validation Report 格式"；原版组 3/3 都没有界定。这一条是本候选的主效应，扩样后**站得住**。
2. **效率差异不成立**：候选的尝试数是 2／2／6，原版是 6／5／3——候选在 r3 退化到与原版相当（它把"有限帮助"扩展成了"顺手把汇总也算完"，多做了 2 次读表 + 4 次聚合）。**因此"候选更省"这一说法必须撤回**；单次读数里的 6→2／27.9k→6.1k 是采样波动，不是稳定效果。

W2 累计（两臂全部运行）：**51 次尝试 / 220,717 tokens**（额度 80／400k 未触顶）、0 未知用量、0 incomplete、settings 哈希未变。

**对 W3 的含义**：停止条件不能只看"目标题的行为门 + 回归题不退化"就宣布净收益——本轮的实测表明同一候选的**成本项可以在重复间翻 3 倍**。W3 的判据需要把"成本/尝试数"从"附带记录"升级成"有区间的观测"，并按"主效应达标 + 回归不退化 + 成本不劣化（容差内）"三条件收束。
