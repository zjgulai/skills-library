## 2. W1：候选区与差异记录（`control/skill-candidate.mjs`）

**接口**：`openCandidate({ root, candidateId, source:{path,digest}, changes, hypothesis, affectedScope, maxBytes?, now? })` → `{ preview, writeCandidate, seal, verify, assertSourceUnchanged, manifest, directory, candidateId }`。

**落盘结构**：`<root>/<candidateId>/{candidate/SKILL.md, candidate.json, candidate.diff}`。

**关键约束（都是可失败的检查，不是文案）**：

| 约束 | 错误码 |
|---|---|
| 根目录必须存在、是目录、非符号链接 | `INVALID_CANDIDATE_ROOT` |
| 候选 id 必须 `^[a-z0-9][a-z0-9-]{2,63}$` | `INVALID_CANDIDATE_ID` |
| 源摘要必须匹配（避免对错版本动手） | `SOURCE_IDENTITY_CHANGED` |
| 同 id 绝不覆盖 | `CANDIDATE_EXISTS` |
| 候选不得改技能名（frontmatter `name` 不变） | `SKILL_NAME_CHANGED` |
| 声明的改动目标必须真实存在（`add` 查候选侧、`edit`/`remove` 查源侧） | `CHANGE_TARGET_MISSING` |
| 候选必须真的改了东西、且不超字节上限、文本良构 | `EMPTY_CHANGE`／`CANDIDATE_TOO_LARGE`／`INVALID_CANDIDATE_TEXT` |
| 未写候选就封存 | `CANDIDATE_NOT_WRITTEN`；封存后再写 `CANDIDATE_SEALED` |
| `verify()` 重算源/候选/diff 三方身份 | `CANDIDATE_IDENTITY_CHANGED`／`DIFF_MISMATCH` |

**验收入口**：`preview()` 给出候选 id、源摘要与名称、改动清单（目标／类型／理由）、假设四元组（claim／evidence／expectedEffect／regressionRisk）、受影响范围——这是 W3 之前给人看的门面，**不含任何金标或终测答案**。

**测试**：`tests/skill-candidate.test.mjs` 11 项，覆盖上表每一行，并断言"整个流程不动源文件"（内容与摘要前后一致）。
