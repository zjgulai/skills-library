**教训（新增 4 条）**
1. **文档与代码「两套 Schema」是本族（pdf2skills 系）的系统性缺陷**：批十四三件全中，且 MECE 那件是 error 级（照文档跑必错）。判者口径很清楚——**文档是契约，代码要向文档对齐**（或在文档里显式收敛），不能两套并存。三件的修法统一为「字段清单两处同源 + 形态迁移 + 报告里标注实际命中的路径」。
2. **「默认会出境」的脚本是安全缺陷，不只是可用性问题**：skill 3 的 `run.py` 默认就把 SKILL 正文与材料 POST 到外网。正解＝默认零出境（`--dry-run`/`--validate` 离线）+ 真实调用显式 `--allow-network` + 不放行时不读密钥。这条与项目的出境纪律一致，可以直接作为**后续批量预置修法**。
3. **复评带点名项时，"修完再评"比带着带病读数写回划算**：三件都走了「基线 → 复评（常带 warning）→ 按点名修完 → 再评」的节奏（8–22 请求/轮），末轮都到 96+。唯一例外是纯 info 项（正文偏长、`evaluated_score` 留空）——那些按惯例登记不轮内改。
4. **自检器先于评审抓到了残留**：skill 3 的 `- **version**: 1.1.0` 是 version-consistency 扫描器在 stage 之后、live 之前报出来的（改完重 stage 再跑）。写回前跑一次扫描器已成固定动作。
