## 2. 契约

`preflight({manifest,capabilities})`返回冻结的`{status:'ready'|'blocked',checks,blockers,preview}`，是**纯函数**：不读文件系统、不读全局配置、不接触密钥；`manifest`是宿主准备的本轮清单，`capabilities`是宿主对"哪些边界已被证据覆盖"的权威记录。

12项检查：`binding / nativeVersion / readBoundary / requestAttempts / stop / authorization / files / tools / model / budget / environment / nativeSession`。任一不通过即产生阻塞码；**缺证据一律阻断**，不降级为警告：

- 清单自身的声明永远不是授权：需要`capabilities.authorizationVerified`与宿主签发的`reference/scopeDigest`一致；清单里塞`approved:true`这类字段直接判`INVALID_MANIFEST`。
- 离线与原生模块级证据不足以启动真实运行：`nativeSessionVerified=false`→`NATIVE_SESSION_UNVERIFIED`（T08未做，故当前真实任务必然阻断）。
- 工具范围必须与冻结白名单完全一致（多一个`bash`/`run_code`阻断、少一个阻断、重复阻断、宿主侧名单漂移阻断）。
- 文件按逻辑ID逐个核对：越权`FILE_NOT_ALLOWED`、内容身份变化`FILE_IDENTITY_CHANGED`、超限`FILE_TOO_LARGE`、缺失`FILE_MISSING`、空材料`NO_MATERIALS`；材料字节与请求预算不匹配时`MATERIAL_BYTES_EXCEED_REQUEST_BUDGET`。
- 模型对必须与宿主批准对逐字一致，且两侧都是非空字符串。
- 所有证据只通过自有数据属性读取，继承来的或访问器提供的"已验证"标记无效；恶意/畸形输入一律阻断而不是抛错（顶层兜底`PREFLIGHT_ERROR`）。

`preview`只含：材料类别（逻辑ID、sha256、字节）、模型对、工具范围、限额与截止；不含绝对路径、金标、密钥或清单里的其它字段。

CLI：`node skill-lifecycle/control/preflight.mjs --manifest <json> [--capabilities <json>]`，只读这两个JSON文件、只向stdout打印一行JSON；退出码 0=ready、3=blocked、2=用法错误（用法写stderr）；**任何情况下都不创建会话、不发请求、不执行任务**。

## 6. 适用限制

T07证明的是"执行前条件"：它能挡住证据不足、身份漂移、范围超出的清单，但**不能**证明真实会话里没有旁路。`files[].maxBytes`是上限而非实测大小，真正的请求尺寸门仍是T06包装器在发送前的实测；preview按计划要求最终必须来自最终请求构造路径，这一点只有T08/T09存在真实装配后才能验证。金标、密钥与私密报告从未进入本模块的输入或输出。
