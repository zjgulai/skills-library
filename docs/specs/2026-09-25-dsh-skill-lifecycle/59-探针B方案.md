## 1. 问题

探针 A 量的是"**模型会不会装错**"（装载层）。探针 B 量的是下一层：
**装了某个库技能，同一个任务的交付质量是否真的更好**——这是"优化/评估"闭环里"收益读数"的最短实验。

## 2. 对象：`81-Skills/Skill评估师`（库内冻结副本）

选它的三个理由：

1. **自带可机械核验的判据**：它定义了状态词表（`excellent` / `good` / `needs_optimization` /
   `needs_refactor`）与发布门槛（**总分 ≥85 且无 error 级问题**），读数不依赖人判；
2. **产物结构化**：报告必须含 `eval_info`/`scores`/`issues`/`optimization_plan`/`status`/`recommendation`，
   `issues` 每条要有 `severity`/`field`/`message`/`fix_type`；
3. **它就是批量评估会用到的那件工具**：量它的收益，等于量你后续"批量优化"这一步的仪器是否有效。

## 3. 材料：6 份待评估技能（4 植入缺陷 + 2 干净对照）

| 题 | 材料 | 植入的缺陷 | 落在 rubric 的哪一项 |
| --- | --- | --- | --- |
| q1 | `p1-desc-no-trigger` | description 只有功能描述，无触发条件/触发词 | description 结构的 40 分档 |
| q2 | `p2-dangerous-body` | 正文直接 `sudo rm -rf`，无任何安全边界 | error 级问题（发布门槛要求无 error） |
| q3 | `p3-missing-reference` | 引用 `references/checklist.md`，包内只有 `notes.md`（包内文件清单随材料给出） | 目录结构/有效引用 |
| q4 | `p4-empty-workflow` | 正文只有一句目标，无工作流/步骤 | Body 内容质量（工作流清晰度） |
| q5 | `p5-clean` | —（干净对照：触发词/何时不用/安全边界齐全，五步工作流，引用存在） | — |
| q6 | `p6-clean-alt` | —（干净对照二，另一领域） | — |

**材料自检（零请求，已做）**：用我方屏检（与 rubric **不同的第二台仪器**）独立跑这 6 份材料——
四道植入题**各只命中一类**（`SHORT_DESCRIPTION`／`DANGEROUS_COMMAND`／`REFERENCED_FILE_MISSING`／`EMPTY_BODY`），
两道干净对照**零发现**。⇒ 缺陷是真缺陷、材料不夹带第二个变量。

## 4. 双臂与预注册判据

- **armed**：注册 `Skill评估师`（连同它的 `references/` 全部随包）；**none**：不注册任何技能。
- 两臂共用同一份任务文本（"评估给定技能，给出发布结论与问题清单"）与同一份材料；
  材料以 fileId 交付，`trial_read` 读取，报告用 `trial_write_report` 写出。

**判据（跑前钉死）**

| # | 判据 | 阈值 |
| --- | --- | --- |
| 1 | **缺陷覆盖率** | armed 臂 4 道植入题里 ≥3 命中 defectTokens，且**严格多于** none 臂 |
| 2 | **误报** | 两臂在 2 道干净对照上均为：`status ∈ {excellent, good}` 且 `issues` 无 error 级 |
| 3 | **结论正确率** | armed 臂 ≥5/6（含两道干净对照必须 release 档） |
| 4 | 成本 | 每执行 ≤10 请求 且 ≤60k tokens |
| 5 | 稳定性 | 2 次重复的读数一致（不一致记波动，**不追改判据**） |

**读数为什么可以机械化**：状态词与发布门槛都是技能自带的词表；**命中匹配限定在 `issues` 区块内**
（干净技能的正文里本来就写着"触发词/安全边界/工作流"，全文匹配会冤杀）；报告若不是 YAML（none 臂可能如此），
则整份回复视为 issues 区块——这条让两臂可比。**不需要盲判**。

### 8.2 两处装配修正（发请求前发现，已改）

1. **技能目录在 `request.tools`、不在 `request.messages`**：探针 A 的目录探针只看 messages，
   在探针 B 上会误报"无目录"；现改为两处都量（这同时把探针 A 的结论口径修正为"两处合并"）。
2. **fileId 必须 ASCII**：挂载点时用 `skill-Skill评估师` 撞上 `[a-zA-Z0-9]` 校验
   （技能名可以是中文，挂载点不行）⇒ 改用 `skill-evaluator`。
