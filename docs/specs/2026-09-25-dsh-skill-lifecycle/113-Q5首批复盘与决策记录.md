## 5. 问题与教训（下一轮要防的）

1. **预算编排**（见 §2 归因）：下批需按上四分位预估 + 明确「这条预算线管到哪一跑」；批中停在门上虽然程序正确，但会打断「一次跑完」的节奏。
2. **运行手册应补「双尺子」条目**：预算是四字段合计口径，软停是 input＋output 口径——两把尺子混用会误判（r214-run1 账本 302k、软停只见 131k）。
3. **运行期产物入包第 3 例**（`__pycache__`，判者当场抓）：根因是测试子进程漏 `-B`（父进程不继承）；修根因＋删产物。「子进程也带 `-B`」升为固定动作。
4. **zsh 不做无引号变量分词**：`$extra` 被当单参数导致 `--remove` 静默 0；多值参数一律展开写，不借变量。
5. **判者偏好左右摇**：同一字段（compatibility 形状、description 长度、tags 语言）不同轮次评价相反——按「唯一正确落点才改」处置，其余逐字登记（本批 3 件 6 处）。
6. **provider 尾部错误特征**：r214-run1 在报告完整产出后落一次 `error:Internal error encountered.`——读数不受影响；登记为已知运行特征，不视为 void。
7. **r193 连发两次 void 且未入账**：连 void 应触发「先查材料/配置再重跑」的检查（当时第二次 void 后未追因），且 void 消耗必须登记（见 §3.3-3）。
