## 1. 终态定义（这个目标什么时候算完成）

## 3. 每技能流程（已复现 7 次，固定四步）

1. **基线轮**：`opt-loop stage/task` → capture（零出境）→ wake-check（零出境）→ **live ×2**（`T_RUN_ATTEMPTS=10`；组闸 60/300k）→ 读问题清单；
2. **修复（零请求）**：产出 gen-1 候选（按 §4 修法库逐条对应基线问题）→ 本地验证（python 编译/自测、屏检、capture）；
3. **复评轮**：同仪器同题只换材料，**live ×2**（void 就补跑，最多 3 次）→ 与基线逐条对照；**若复评冒出 error/质量门槛级新问题，追加一代（gen-2/gen-3），预算按 2–3 代留**；
4. **写回**：`skill-repair-writeback`（dry-run 0 拒 → apply）＋`skill-repair-rename`（nextDir）→ 核验（库内==候选逐字、`yaml.parse`、库内自测、屏检、四路装载）。

## 5. 成本模型与预算（实测）

- 每技能 **34–107 请求 / 0.14–0.60M tokens**（hub、长包、需 2–3 代者偏上）；void 率 ~15%（读取耗尽为主，偶发 429）。

- 零请求部分（修复/写回/台账/核验）不占额度，但**必须留档**。
