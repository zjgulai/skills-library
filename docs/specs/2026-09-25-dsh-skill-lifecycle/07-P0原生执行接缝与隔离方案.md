# 07｜P0：DSH 原生执行接缝与隔离方案

调查日期：2026-09-25。状态：只读静态核验完成，动态调用未运行；隔离与预算控制尚未实现。首轮业务范围已确认，见[任务卡](05-试点选择与任务卡.md)。静态证据摘要：[p0-static-findings.json](evidence/p0-static-findings.json)。

## 1. 推荐结论

优先复用 Desktop 原生会话链路，创建专用测试作用域／岗位，不复用历史对话，也不修改既有业务岗位。使用当前安装产物的能力，不把 PATH 上另一个版本的 `dsh` 当作 Desktop 的等价运行时。

这个推荐尚不等于可以马上运行：只指定新会话与 cwd，不足以保证文件只读范围、金标不可见或工具无旁路。P0 首要补齐并验证工具访问边界，再做少量获准模型请求。设置一个新的数据目录也只隔离部分运行状态，不天然隔离宿主文件。

不新建通用编排平台、不默认修改 DSH 应用 bundle、不绕过权限。具体测试岗位或控制插件尚未创建，接入实现需要另行批准。

## 3. 已核对的原生执行接缝

共同包前缀：`/Applications/DSH Desktop.app/Contents/Resources/app/node_modules/@deepseek-ai/`。

| 接缝 | 静态实现 | 使用限制 |
|---|---|---|
| 新建普通会话 | `dsh-api-session-controller/lib/index.js:571–598` 的 `create(request)`；未给sessionId时生成新ID，支持cwd或workspaceId以及agentPreset | 会创建／持久化会话，不是无痕dry-run；本轮未调用 |
| 提交任务 | 同文件 `:736` 的 `prompt(request)` | 这是后续模型执行入口，必须先获准数据和预算 |
| 选择模型 | 同文件 `:605–633` 的 `selectModel(request)` | 除会话选择外，`:621`调用 `agentDefaultModel.saveSelection`，可能改变全局默认；不能当无副作用会话操作 |
| 跟踪事件 | 同文件 `:1400–1467` 的 `follow(request, signal)`；开场快照、序号事件，可选assistant流 | 流取消不等于任务取消；完整流可能带正文，导出须按字段范围处理 |
| 取消任务 | 同文件 `:872–877` 的 `cancel(request)` 调用 `agent.cancel(...,{keepInbox:true})` | 保留排队inbox，不能视为阻止全部后续任务；取消收到确认不证明费用停止或进程已空闲 |
| 用量类型 | `dsh-api-session-controller/lib/typert.host.js:2018` | inputTokens/outputTokens存在类型定义，total/cache/reasoning可选；实际返回须观察，缺失记unknown |
| 限定技能发现 | `dsh-skill-filesystem/lib/index.js:31–44,73–85` | 配置有includeDefaultRoots、customSkillDirs、watch、bundledSkillDir；还要检查其他provider和岗位作用域 |

这些是安装代码内部服务方法，不是已经证明可直接从当前会话调用的公开HTTP接口。后续仍须核对受支持的宿主接入方式，不猜URL或跨版本调用。

## 4. 三个阻止直接基线运行的缺口

### 4.1 文件读取隔离不成立

`dsh-fs-sandbox/lib/index.js:69–91` 明确说明策略主要限制写入，读取在各模式下直接通过；`:125–140` 只在writeText/editText进入写入边界检查。workspace-write允许工作目录及平台临时区域，不等于“只能写一个产物子目录”。

因此，不能把金标放在另一目录就宣布对执行者不可读。Bash还存在独立策略，文件工具、脚本和其他MCP的覆盖要逐项核对。不能只修文件读取工具而保留一个能任意读取宿主文件的shell旁路。

### 4.2 总预算不等于maxTokens

检查到模型单次输出限制和用量类型，但尚未证明有整批任务累计预算、模型请求数和步数的统一硬门槛。P0需要在新请求开始前检查预算，并记录实际用量；缺用量时不能按0计费。若无法预估请求最大成本，不能承诺绝不超过精确金额上限。

### 4.3 会话取消不等于工作流终止

原生sessionController.cancel保留inbox；后续核对发现内部agent句柄支持 `cancel(cause,{keepInbox:false})` 与 `whenIdle()`，详见[08控制契约](08-P0读取预算与终止控制契约.md)。二者语义不能混用，且仍需外层持久关闭准入。控制层应在超时／预算到限时停止排入新任务，取消当前执行，观察真实终止状态，并把未完成记录标为不完整。不能重新创建会话继续跑而重置预算，也不能收到accepted就宣布所有执行已停止。

## 5. 拟定最小测试作用域

设计建议，不是已实施配置：

1. 专用测试岗位／作用域按明确白名单装配；参考数据岗位的相关行为，但不继承其所有权限、插件和外部连接。
2. 执行者只获得本次允许的输入、被测Skill和自己的输出区；裁判答案、其他运行产物和原始源库不进入其可访问集合。
3. 被测Skill从已冻结内容装配，原版和候选分开运行；目录集合和同名胜出项必须记录。
4. 用于计算的工具也要被限制在同一边界；若通用Bash无法满足限制，先核对受控计算入口或可执行隔离方案，不能仅靠提示词禁止读取。
5. 独立裁判可读所需答案和产物，但不修改目标执行结果；优化者只读开发反馈。源库不被任何自动修复入口写入。
6. 只有宿主模型传输可按许可访问必要服务；不因此开放执行者的任意网络。预览传输类别、大小和版本，不复制凭据。

隔离要用无敏感的哨兵文件验证：允许输入可读、未授权哨兵不可读、输出区可写、受保护区不可写、路径穿越和软链接不能越界。不要读取真实私人文件来证明拒绝机制。

若现有Desktop作用域不能安全装配以上边界，需要先补最小控制接缝并验证，或提出独立同版本Host方案供决策；不能悄悄切换成不同运行栈并继续声称Desktop原生验收。

## 6. 默认模型与岗位建议

建议首轮采用用户当前默认模型作为可比起点，但必须确认实际选择，不能只根据设置文件推断。若改模型，不直接调用会保存全局默认的selectModel而不告知；应先确定不影响日常使用的局部配置方式。

岗位使用专用测试作用域，`agt-046`仅作为相关环境参考。后续需要保留多少相邻技能，应由“真实代表性”与隔离边界共同决定，而不是为了减少误触发移除所有竞争者。

## 7. 分步实施与验收建议

| 步骤 | 交付 | 可证明 | 不能证明 |
|---|---|---|---|
| P0-1 静态预检设计 | 当前版本／装配／路径／字段清单 | 要调用的接口与边界有来源 | 实际模型和沙箱运行有效 |
| P0-2 无模型控制验证 | 版本错配、缺记录、预算到限、状态恢复的测试 | 控制逻辑不会凭空通过 | 模拟事件不是DSH真实事件 |
| P0-3 原生隔离与生命周期验证 | 新会话、技能来源、无敏感哨兵边界、停止与恢复证据 | 指定运行路径满足要求 | 不能外推未装配工具 |
| P0-4 小批获准真实探针 | 少量公开任务的原生轨迹与产物 | 模型链路、用量和业务检查可工作 | 不能据少量样例宣称统计稳定或候选有增益 |
| P1 正式基线与优化 | 预定任务集、比较、回归、终测与证据 | 限定范围内候选是否值得保留 | 不自动授权生产启用 |

本轮完成的是静态调查与文档，不是上述验证脚本、测试岗位或真实探针的实现。
