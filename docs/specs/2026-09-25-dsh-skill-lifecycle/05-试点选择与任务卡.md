## 2. 为什么选择它

1. 与用户原来的促销／经营分析复盘材料接近，有真实应用意义，而不是为了测工具构造空任务。
2. 输入可限于公开或合成的本地分析报告和小型表格；不必先连接账号、线上数据库或生产数据。
3. 同时有可复算项目和判断项目：指标、聚合和时间口径可核算；结论是否受证据支持、缺数据如何说明需要判断。
4. 任务边界清楚：核验已有分析，而不是重新生产所有分析或直接发送给利益相关方。
5. 有既有输出契约，便于测量候选是否保持功能并减少错误；无效优化可以明确拒绝。
6. 名称与描述可用于 DSH 的显式／自然选择测试，且有统计分析和作图等自然近邻。

它虽然也是一种“核验”技能，但检查的是业务分析，不是元技能自身的评分器；目标执行与元评测裁判必须分开，不能让它为自己的优化结果评分。

## 6. 公开开发覆盖方向

这里只定义能力类别，不生成题目答案或隐藏集。

- 正确且证据充分的分析，检查不应编造缺陷。
- 有可独立复算的聚合或分母问题，检查要给出依据。
- 比较期间、总体或指标定义不一致，判断要定位口径而非只算数。
- 结论超出数据能支持的程度，能限定因果与不确定性。
- 缺原始数据或范围说明，能明确未验证部分。
- 合法边界值与真正数据异常，按指标语义区分。
- 请求是重新做统计分析／画图／解释术语而不是核验，考察近邻选择边界。

使用公开或合成输入也必须在真实DSH执行，不用手工模拟模型回答冒充验证。隐藏终测要在另一个受保护流程中建立，不能从本文件原样复制例子后声称独立。

## 7. 必需门槛和暂不钉死的指标

首轮不可接受行为：虚构工具执行或已验证计算；擅自外发数据；修改源或裁判；报告指向错误输入版本；把关键缺失证据当足够依据。发现这些问题，相关验收不通过。

业务综合指标、误报／漏报容忍度、样本量、重复次数和成本改善要求，待正式任务集与基线口径确认。不能因为选中了技能就假设一定需要修改；若原版满足目标且候选无增益，应保留原版。

### 分开管理三类预算

- 任务执行数：一题在一个配置下的一次完整 Agent 执行；其中可能包含多次模型请求和工具调用。
- 模型使用量：累计输入、缓存口径和输出用量；`maxTokens` 等单次输出限制不等于总 token 或费用上限。
- 墙钟与重试：每次任务超时、整个批次预算和可重试次数；中断恢复不能重置累计额度。

第一批建议仅用于执行接缝与基线可行性验证，不宣称统计稳定或技能改善。具体题数、步数和预算将在DSH实际可观测字段与可强制限额核对后提出；没有价格与使用量依据时不估造人民币成本。
