# 35｜P2-1 需求接收与契约草稿（2026-09-27）

按 [34-P2–P4 工程化计划](34-P2P4工程化计划.md) 实施的第一步。**纯工程、零真实请求。**

## 交付物

`control/requirement-intake.mjs`：`draftContract({ requirement, signals, draft })` → 三值结论 + 契约草稿。

- **信号三键**（必须显式给布尔）：`recurring`（是否重复发生）、`existingSkillCovers`（是否已有技能覆盖）、`needsJudgment`（是否含需要判断的成分）。
- **判定规则（先钉死）**：`existingSkillCovers` → `not-worth-skillifying`；否则 `recurring === false` → `not-worth-skillifying`（一次性需求）；否则未给草稿 → `needs-user-input`；给了草稿且**不含阻断性未决问题** → `draftable`；草稿里出现 `BLOCKING:`/`阻断` 前缀的未决问题 → 降为 `needs-user-input`。
- **契约字段**（六项，均需提供）：`triggers` / `inputs` / `outputs` / `constraints`（至少 1 条）＋ `outOfScope` / `openQuestions`（可为空）；每项 ≤12 条、每条 ≤500 字符；`need` 取自需求原文，不由草稿覆盖。
- **"不建"只看信号，不看措辞**：测试里专门验证"prose 承诺重复但信号 `recurring:false`"与"prose 声称没有覆盖但信号 `existingSkillCovers:true`"都必须走 `not-worth-skillifying`。
