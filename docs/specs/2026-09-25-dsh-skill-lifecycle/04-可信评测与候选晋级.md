# 04｜可信评测与候选晋级

状态：设计建议，需结合试点确认执行预算和具体指标。已确认不使用综合分单独决定通过，不允许优化者改裁判自评晋级。

## 1. 比较问题先定义

主比较：原版 vs 候选。辅助比较：无目标 Skill vs 原版，用于判断当前模型是否仍需要此技能。两者回答不同问题，不能混用。

主要目标由任务卡确定：任务结果改善、自然选择改善，或维持质量下降总成本。先定义必须保留的行为、可接受回归和成本边界；看见结果后改门槛必须留痕并重新评价，不能悄悄提高自身成绩。

## 2. 三类集合与信息边界

| 集合 | 可用信息 | 用途 | 限制 |
|---|---|---|---|
| 开发集 | 输入、输出、结果和允许的反馈可给优化者 | 定位问题与调试候选 | 不用于独立效果宣称 |
| 验证集 | 受控比较结果供选择候选；内容暴露范围要记录 | 候选选择与停止 | 反复用于选择后不能称未见终测 |
| 终测集 | 被测执行者仅得到完成本题所需输入，裁判持有答案 | 最终独立验收 | 不向优化者公开答案或用于同轮迭代 |

本次归档不创建真实题集或金标，不提前发布隐藏答案。后续数据来自公开或合成业务场景，不能偷偷使用私人生产数据。

题集、金标、评分器和版本关联固定。不能先读取全量答案再分组，然后宣称优化者与留出集隔离。终测反馈用于改进后，相关样本转为已知回归样本，另建新的独立终测。

## 3. 测什么

1. **格式和执行条件**：文件解析、引用、必要依赖；只证明能开始相应运行。
2. **内容能力**：明确加载后，实际产物是否满足业务标准。
3. **自然选择**：正例、近邻负例、隐含需求以及应澄清的情况。
4. **原有行为回归**：当前版本已能完成且不能破坏的任务。
5. **权限和证据边界**：缺证据、工具失败、受保护写入、输入中的不可信指令。
6. **成本与稳定性**：耗时、总调用量、人工介入、重复运行差异、中断恢复。

有引用资源才测相应资源路径；无脚本不因目录空缺扣质量分；限定试点不能代表未覆盖的工具和领域。

## 4. 怎样判

- 程序：计算、数据聚合、格式、文件身份、明确副作用等可机械判定项。
- 人或经校准的模型裁判：方法适切性、证据支持程度、误报、不确定性表达和建议质量。
- 裁判可以组合，必须给出证据；不能要求有效答案逐字命中唯一句子，也不能用“报告存在”代替语义正确。
- `pass`：规定范围证据充分且标准满足；`fail`：证据表明标准不满足；`inconclusive`：缺结果、范围不符或证据不足。
- 运行 `blocked/error/cancelled/budget_exhausted` 与业务 `fail` 分开。缺失样本必须计入完整性与覆盖率，不静默剔除。

统计F1时仅对标签与预测空间一致的路由问题计算。澄清是有语义的行为，不是一律跳过；应在题目政策中明确它是正确行为、错误行为还是本轮不可判，并报告覆盖。安全是否发生要看工具和数据行为，不由“无路由FP”推导。

## 5. 可比性

- 固定模型版本／参数、DSH版本、工具权限、输入、初态、裁判及预算口径。
- 使用干净上下文与输出区，防止聊天、缓存、Git历史、共享文件或答案进入基线。
- 原版与候选保持同一任务和逻辑技能身份，分开装配；不能同时更换工具能力然后将收益全归技能。
- 重复次数和样本量在预算获准后设置，按风险和希望分辨的差异决定；不得把几次全绿当稳定率证明。
- 耗时和成本应包含候选生成、失败试验、裁判等相关成本，并明确与单次运行成本区别。
- 若依赖平台的真实随机性无法完全控制，记录而非虚构可重复性。差异证据不足时保留原版或继续收集，不保证每轮必胜。

## 6. 候选可交付的门槛

所有下列门槛成立，才可标“候选可交付”；它不是生产发布授权。

| 门槛 | 要求 |
|---|---|
| 证据身份 | 测试、产物、候选、原版、裁判和环境对应同一记录 |
| 完整性 | 必需运行和结果齐全，未跑不能当通过 |
| 业务关键项 | 预先定义的关键错误和虚假完成判定未出现 |
| 风险边界 | 没有不可接受的越权／外发／裁判污染；缺证据阻断 |
| 回归 | 必须保留能力没有超过事前政策的退步 |
| 主目标 | 足够证据支持改善，而不是仅靠模板或文件齐全 |
| 成本 | 在获准预算和预定运行代价范围内 |
| 独立终测 | 合格候选完成独立终测；首次即达标也不能自动免终测 |

每个门槛有独立布尔或未知状态。总分可辅助排序，不允许平均值补偿关键项失败。

## 7. 裁判自身先验收

用已知预期的控制反例检查：没有运行记录；技能哈希不匹配；验错版本；遗漏轮次；只有触发正确但结果错；假装使用工具；受保护答案或评分文件被改；合法未知被误判通过；正确结果被关键词裁判误杀。

这些是验证评测设施的公开控制用例，不是目标技能的隐藏终测。它们与后续业务金标分开。第一轮不拿元评测器依其自定标准自评作为有效性证明。

### P0 无模型请求预检与真实调用分开

无模型预检只检查执行计划、路径、内容身份、事件处理与预算门禁，不给目标技能生成质量分数。模拟事件用于测试控制逻辑时，必须标注模拟，不能充当DSH真实事件或模型运行证据。实际模型请求只能在边界和预算获准后发生。

第一次真实请求前，应能展示：将发送的材料类别和大小、技能内容身份、目标模型、允许工具与读写范围、调用次数与步数上限、每次请求最大输出、超时和超预算时的停止动作。如果原生接口无法实施某项硬约束，就明确阻断或补齐控制，不以“模型会遵守”代替。

预算耗尽后应停止新请求，尽可能取消在途任务并保存已知状态；取消是否仍计费由服务端决定，不能保证撤销已发生费用。达到上限后只有新的明确授权可继续，不能用重试、新会话或恢复动作重置额度。

完整预算和终止协议见[08-P0控制契约](08-P0读取预算与终止控制契约.md)：每次provider尝试含重试都需计数，发送前预留、结束后结算，缺用量保留未决而非记零；终止先关闭准入再取消并核对空闲。首版工具白名单会改变可执行环境，必须对原版和候选同等实施，不能把工具收缩带来的差异算作技能优化效果。

## 8. 本试点保持的语义

`validate-data` 已有三种业务建议：`Ready to share`、`Share with caveats`、`Needs revision`。这是被测技能的业务输出，不直接对应工作流是否晋级。首轮默认保留该契约；不能未经确认把它改为完全不同的三个状态，再声称旧能力无回归。

评测器另设“证据是否足够、检查是否实际发生”的内部状态。例如原始数据缺失时，任何建议都必须说明未验证哪些计算，不能伪造verified。业务标签与内部证据状态应分开判定。

## 9. 实验开始前的待定项

首轮任务范围与保持原业务输出契约已确认。目标 DSH 岗位与模型、调用预算、任务与重复次数、主指标及容忍变化、独立终测保管方式、原始记录保留和脱敏范围仍须在执行前确定。以上不是本次文档可自行拍板的实际执行许可。

模型传输是本地任务中的独立边界：即使任务不允许浏览器或业务工具联网，模型服务仍可能收到用户请求、技能正文、输入数据与工具结果。测试只采用经确认的公开或合成材料；首次真实调用前必须预览会发送的字段、内容类别和大小，不读取或复制生产凭据进报告。限制业务工具网络不等于整个运行没有数据出境。
