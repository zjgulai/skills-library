## 1. 依赖登记：`control/dependency-registry.mjs`（6 项测试）

**它解决什么**：`change-plans` 的 `dependents` 之前"由调用方给"——依赖事实没有自有来源，等于谁写计划谁编依赖。现在有一份 append-only 的登记（`<root>/governance/dependencies.jsonl`，与处置账本同区）：

- 一条事实＝`{ dependent: { kind, id }, provider: { skillId, version }, evidenceRef, recordedAt }`；`kind ∈ {terminal-set, task-set, candidate, install, skill}`。
- **同一条事实不会记两遍**（`DUPLICATE_DEPENDENCY`）；字段级严格校验；写入走 `appendFile`（append-only 有行为断言）。
- 读取 fail-closed：篡改过的行（内容与封存 id 不符）→ `DEPENDENCY_TAMPERED: line N`，查询直接拒答。
- `dependentsOf({ registry, provider })` 把登记翻译成**规划器直接可吃的形状**。规划器那个字段叫 `skillId`（当年只为技能命名），而依赖方常常不是技能——所以上报身份写成 **`<kind>-<id>`**（如 `terminal-set-w03`），kind 不会溶解在一个裸 id 里。
- **闭环验证**：登记里的事实 → `dependentsOf` → `planRetire`：有依赖不给迁移说明就 `MIGRATION_REQUIRED`，给了就进 `impact.dependents`。这条链在测试里真跑过。

**变异验证**（4 处）：去掉重复检查 → 1 红；`appendFile` 改 `writeFile` → 2 红（append-only＋派生形状用例）；去掉内容摘要比对 → 1 红；`dependentsOf` 丢掉 kind 前缀 → 1 红。全部还原。

## 2. A5 归因自动化：`control/attribution.mjs`（8 项测试）

**它解决什么**：「失败读数 → 假设 → 改动建议」此前整段靠人（21 号：读数交独立 agent 产出候选）。现在拆成**机器做读、人做判断、机器校验判断**：

- `buildAttributionBrief({ records, gateTokens, criteria })`（纯函数，复用 `iteration-loop.collectObservations`）产出**每道失败题的事实**：`readings`（`INCOMPLETE`／`REPORT_MISSING`／`GATE_MISSED`／`COST_OUTLIER`，可多条）、逐次重复的 `evidence`（门、完整性、报告、尝试、tokens）、以及 **`criteriaVisible`**——该题是否在预注册判据（target／regression）之内。
- **把 P1 的教训做成机制**：不在判据内的失败题会被单独列进 `hiddenFromCriteria` 与 `limits`（"N 道失败题不在预注册判据内（改进不会被计分）"）。这正是当初"候选真实改进因判据不含该项而未晋级"的事故形态，现在它在出题阶段就被点名。
- `submitHypotheses({ brief, hypotheses })` 校验人的判断：题必须在 brief 里（`UNKNOWN_FAILURE`）、每道失败题要么给假设要么显式豁免并写理由（`UNATTRIBUTED_TASKS`）；**`criteriaImpact` 必须与 brief 的 `criteriaVisible` 一致**（`CRITERIA_CLAIM_MISMATCH`，两个方向都拦：既不许把看不见的改进说成会加分，也不许把看得见的说成看不见）；声明 `not-covered` 必须写清"怎样才能被看见"（`COVERAGE_NOTE_REQUIRED`）。产出 `coverageGaps` 与 `waived` 两张清单＋`reportDigest`。
- `toCandidateHypothesis({ report, taskId })` 把一条**已接受**的假设翻成候选要的 `{claim, expectedEffect}`；判据看不见的那类**不许**这样进候选（`COVERAGE_NOTE_REQUIRED`）——"改进了但不会被计分"不能装作会。

**边界（明写）**：机器只做"读数与校验"，**改什么仍由人（或独立 agent）判断**——这是设计，不是缺口；`brief.limits` 也会说明样本量与成本口径（tokens／尝试数，无价格依据）。

**变异验证**（5 处）：`criteriaVisible` 恒真 → 1 红；去掉 `criteriaImpact` 一致性校验 → 1 红；去掉"not-covered 必须写覆盖说明" → 3 红；去掉未归属检查 → 2 红；去掉未知题检查 → 1 红。全部还原。
