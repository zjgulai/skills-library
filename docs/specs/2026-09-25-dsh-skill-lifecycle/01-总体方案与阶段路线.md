# 01｜总体方案与阶段路线

状态：方向已确认，机制细则待审阅。范围：DSH 专用。

## 1. 问题陈述

现有材料已经包含创建、体检、评测、优化、核对、管理六类元 Skill，也有评分、报告与副本工具。但静态研究发现评分依据、信息隔离、缺证据默认行为、完整回滚和实际 DSH 装配尚不能支撑直接生产放行。需要把“按说明执行”补成“关键状态与边界能被验证的工作流”。

目标不是保证每个 Skill 都被改写，而是自动判断哪里值得改、产生候选，并证明候选在指定 DSH 环境中是否带来净收益。允许结论为保留原版、证据不足或运行受阻。

## 2. 已确认范围

- 只考虑 DSH；暂不做 Claude、Qoder 等其他平台兼容。
- 生命周期完整设计、分阶段交付，每阶段在真实 DSH 条件下验收。
- 先走 A：一次一个已有 Skill 优化，不从元评测器自评自己开始。
- 首轮试点为 validate-data，核验本地经营分析报告＋小型表格，保持原业务输出契约；实际模型／岗位与调用预算未因此获准。
- 源技能只读，修改候选副本；生产启用另行批准。
- 优化者不能自行改裁判、金标、授权或成功标准。
- 缺证据不是通过，技能加载和报告生成也不是业务成功。
- 优先复用已审查的六角色职责与必要脚本，不要求六个常驻 Agent。

## 3. 总体分工

| 层 | 责任 | 不承担 |
|---|---|---|
| 管理入口 Skill | 解释需求、展示状态、请求决策、引导流程 | 凭语言自述推进受控状态 |
| 工作职责 Skill | 分析、提出假设、生成候选、解释结果 | 自签发布、修改受保护裁判 |
| DSH 执行与控制 | 创建运行、装配范围、工具执行、权限、预算、状态恢复 | 自动判断所有业务真伪 |
| 评测与证据 | 定义检查、实际采集、结果校验、比较与回归 | 以报告完整性代替来源真实性 |
| 用户／授权政策 | 决定预算、数据边界及生产启用 | 为未经验证的结果补作证明 |

“控制层”是拟建设的责任集合，不预设必须新建服务或改 DSH 内核。先核对现有 DSH 接口；能直接复用的复用，缺口才由受控脚本或集成补齐。没有核验前不编造 API 名称或运行命令。

## 4. 完整生命周期

需求／已有 Skill／运行反馈 → 价值与范围判断 → 契约与评测设计 → 创建或修改候选 → 结构检查 → 真实执行与比较 → 证据核对 → 待批准 → 限定岗位启用 → 运行观察 → 保留／优化／合并／退役／回退。

不是每次都走完整链：已有技能请求从评估开始；反馈先归因，不必每次生成候选；不值得技能化的需求正常结束；发布、退役和生产回退必须遵守各自授权。

## 5. 分阶段建设

| 阶段 | 交付边界 | 自动动作 | 保留人工决定 | 阶段验收 |
|---|---|---|---|---|
| P0 可信基础 | 能记录、验证、阻断和恢复一个实验 | 内容身份、检查、运行证据、受控状态、预算累计 | 首次环境与权限安排、预算 | 无结果不通过；版本错配拒绝；中断不丢进度或清零预算 |
| P1 已有技能优化（A） | 原版到候选与比较报告 | 基线、候选、回归、证据核对，有限迭代 | 目标、契约变更、超预算 | 源未变；原版和候选可比；无收益保留原版 |
| P2 从需求新建 | 新候选接入同一评测链 | 需求分析、契约草稿、必要资源 | 模糊核心需求、必要授权 | 允许不建；不以生成目录代替能力证明 |
| P3 受控启用 | 批准后限定装配与可回退 | 变更预览、安装核对、观察、授权范围内回退 | 具体版本与目标岗位启用 | 实际加载正确版本；回退完整；不混中间态 |
| P4 持续治理 | 反馈进入下一轮候选 | 收集脱敏、候选经验、依赖与价值复测 | 高后果经验采纳、生产变更 | 来源可追溯；经验不直接升格权威；支持合并与退役 |

P0的T01—T08已完成本地实现（状态、受限文件、纯计算、批次预算、停止编排、原生接入、执行前门、专用装配），共275项测试通过；T06为原生模块级、T07为执行前门、T08为窄服务图里的真实会话回合，当前证据见[17-T08记录](17-T08实现与验证记录.md)，历史10—16记录保留。T09真实探针及P1—P4仍未完成。早先[DSH接缝调查](07-P0原生执行接缝与隔离方案.md)仅为静态依据，本地数据处理链路通过不等于原生Agent全路径隔离或业务效果通过。P1前仍需证明必要P0控制。

## 6. A 的用户故事

- A-US01：用户提供已有 Skill 与优化目标，系统识别缺少的核心输入并解释能做与不能做的范围。
- A-US02：系统记录源内容和目标 DSH 条件，原版在全过程保持不变。
- A-US03：发现危险操作、缺依赖或隔离不足时，阻断相应执行，保留原因而非给低质量模拟结果。
- A-US04：原版在干净会话中运行，结果与证据对应同一内容身份和测试定义。
- A-US05：优化者只根据允许的开发反馈修改候选，不读取受保护终测答案。
- A-US06：候选与原版在可比条件下比较，结果包括失败、成本、覆盖与不确定性。
- A-US07：缺关键结果、错版本、关键回归或风险越界时，不能产出“可交付”状态。
- A-US08：中断后复用已完成且身份匹配的阶段，不重复外部副作用，不重置预算。
- A-US09：用户拿到候选、差异、证据和使用限制；没有批准时不更新生产安装。
- A-US10：没有足够改善时保留原版，并留下可解释结论。

## 7. 明确不做

跨平台适配、全量技能库自动改写、自动修改生产岗位、自动放宽权限、通用技能市场、训练模型权重、未经确认的知识库全文上传、无人审批的自发布、为了演示而增加多 Agent 分工。
