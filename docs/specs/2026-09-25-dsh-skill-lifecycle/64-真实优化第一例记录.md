## 2. 这一例证明了三件事

1. **评估器能当"改进目标生成器"用**：它给出的 issues **可执行、可复核**（点名字段＋严重度＋修法），
   且**抓到了我静态层漏掉的一类问题**——正文里的**跨技能相对路径** `../某某技能/`
   （我的屏检只认 `references/` 这类包内前缀，`../` 出不了家门 ⇒ **识别出屏检的一个缺口**，见 §4）；
2. **改完能复评**：同一仪器、同一题、只换材料 ⇒ 分数与 issues 的变化可直接对照；
3. **它会抓到我引入的新问题**：候选 1 代把"脚本脱节"改成"跑脚本"，立刻被指出与安全边界冲突——
   这条如果只靠人工自检，很可能漏。

## 4. 顺带发现（登记）

1. **屏检缺口**：`../<技能目录>/` 这类**跨技能相对引用**不在判据内（只认包内目录前缀）——
   评估器在 R1 就抓到了它。⇒ 待补规则（`CROSS_SKILL_RELATIVE_PATH`，medium：单独分发会断）；
2. **报告契约偶发漏写**：6 次执行里有 2 次模型只在对话里作答、没调 `trial_write_report`
   （执行器已补记**完整回复文本** `replyText`，读数可退回对话文本；probe-b 的 rev2 判据本来就写了"非 YAML 时整篇视为 issues 区块"）；

## 7. 屏检补规则：`CROSS_SKILL_RELATIVE_PATH`（评估器抓到的那一类）

由来：R1 评估点出"正文引用 `../亚马逊竞品监控` 单独分发会断"，而我的屏检**看不见**它——
既有规则只认 `references/`／`assets/` 这类**包内前缀**，`../` 出不了家门。

- 规则：正文（去围栏）里 markdown 链接目标以 `../` 开头 → `CROSS_SKILL_RELATIVE_PATH`（medium，措辞写明"单独分发时会断，改用技能标识符"）；
