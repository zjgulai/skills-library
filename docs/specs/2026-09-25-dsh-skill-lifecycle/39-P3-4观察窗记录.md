# 39｜P3-4 观察窗（2026-09-27）

按 [34-P2–P4 工程化计划](34P2P4工程化计划.md) 实施。**纯工程、零真实请求**；目标只限 `trial-home`。

## 交付物

**1. `control/enablement.mjs` 的 `observeInstalled()`**
- **前置校验两层**：① 树非空；② 若给了 `expectedFiles`（通常直接取安装回执的 `files`）则**逐文件比对**——树不是当初装的那一份就 `INSTALLED_STATE_DRIFT`（防止"观察一个已被改动的树"）。
- **出境门在观察之前**：`observation.mode === 'live'` 且未显式 `allowEgress: true` → `EGRESS_NOT_AUTHORIZED`，**观察器一次都不会被调用**；观察器返回的 mode 与声明不符 → `INVALID_OBSERVATION_RESULT`。
- **观察结果入回执**：`{skillId, candidateId, observedAt, installedDigest, observation:{mode, ok, detail, durationMs, files}}`，写 `<receiptRoot>/<skillId>-observation-<ts>.receipt.json`，**已存在不覆盖**。**失败也照样记录**（`ok:false` + detail），不静默丢弃。

**2. `trial-home/enabled-smoke.mjs` 的 `smokeObserver()`** —— 我们这条工作线上"冒烟"的真实实现，**构造上零出境**：
- 挂上 W4 已验证的原生技能链（`skill-registry` + `skill-filesystem`（`watch:false`、隔离家目录）＋`tool-skill`），`customSkillDirs` 指向**已安装树的父目录**；
- 用真实的 `skill` 工具加载该技能，**不挂任何 provider 路由**（返回值里明确 `route: 'none'`）；
- 断言**服务内容 == 树的 SKILL.md 内容**（去 frontmatter 后逐字节哈希比对）——即"真能被原生工具装上并读出正确内容"。

**两个检查的分工（写清楚，避免误读）**：`smokeObserver` 负责"**加载通路**正确"（服务内容 == 树内容）；`observeInstalled(expectedFiles)` 负责"**树 == 安装身份**"。两者串联起来才是"装上的就是核准的那一份，而且读得出来"。
