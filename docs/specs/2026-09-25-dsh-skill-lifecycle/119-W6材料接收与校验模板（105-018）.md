# 119 W6·105-018 材料接收与校验模板（执行记录）

范围：W6 资料补充闭环的第一件——把 104 号 03 号清单 G01—G11 的"请提供材料"变成**可执行接收流程**（用户分批提供 → 校验 → 制作/修复候选 → W4 同款验证）。**零请求**。

交付：`119-w6-intake/material-intake-template-v1.md`（可填回执模板）＋ `119-w6-intake/g-supplement-status-v1.json`（G01—G11 状态与六要素初判）。

## 1. 六要素（票面验证口径；出处＝104 号 03 号清单 §4）

| 要素 | 定义 |
|---|---|
| ① 用于谁、做什么 | 角色ID＋具体任务（不只写部门） |
| ② 输入与输出 | 一份脱敏输入＋一份认可输出；附"不应通过"的反例 |
| ③ 依据与版本 | 作者/来源、适用市场/产品/日期、许可与是否允许商业使用 |
| ④ 判断与边界 | 哪些规则固定、哪些必须确认、哪些不能自动做；未知标未知 |
| ⑤ 完整资源 | SKILL、references、scripts、templates、依赖与测试（不要只有标题的截图） |
| ⑥ 敏感范围 | 剔除了哪些（密钥/PII/客户明细/未授权）；**脱敏是否改变判断条件** |

**验证方式**：每批材料**逐份回执**（模板一节/份，六要素各标 齐/部分/缺）＋批级汇总表；回执即证据。例子按"正常/边界/失败"三类组织为**建议**（§4 原文），不作为统计充分性判据。

## 2. 接收与校验流水线（模板内置）

1. **接收**：材料放 `trial-home/intake/<BATCH-ID>/`（原始完整包即可，不要求重排）；正文落包，链接只作指引。
2. **登记**：逐文件记录 名称/sha256/size/来源/敏感标记（批回执内）。
3. **文件级校验（零请求，沿用既有工具纪律）**：存在/可读、UTF-8、不透明容器检查（`looksOpaque` 系列）、敏感模式扫描（**注意 `sk-` 会误中技能名一类假阳性，命中先人工辨认**）。
4. **六要素回执**：逐份填模板（齐/部分/缺＋原文引用）。
5. **去向分档**：制作候选（新技能/资源）／修复候选（W4 同款：静态修复零请求、行为验证另批授权）／登记（不制作）／退回补件（点名缺的要素）。
6. **台账回填**：`g-supplement-status-v1.json` 的 `received[]` 追加；批回执落 `intake-receipt-<BATCH-ID>.json`。

**授权门**：接收与校验不涉授权；**制作/修复进既有链路**；**真实请求评测按既有"授权并继续"逐批走预算**。

**机读件已实现（2026-10-01，R-3 预备，零请求）**：`skill-lifecycle/control/intake-check.mjs`——步骤 2/3 的机器部分一次跑完：清单登记（名称/size/sha256）＋旗标（`EMPTY_FILE`／`NON_UTF8`／`OPAQUE_CONTAINER`〔88 7d 1c〕／`SUSPECT_ZERO_FILL`）＋敏感模式扫描（`sk-`／私钥头／`AKIA…`／`.credentials.yaml`／key 赋值，命中带行号与 40 字上下文；**照实标记、人工辨认假阳性**）；dry-run 默认、`--apply` 落 `intake-receipt-<BATCH-ID>.json`（已存在拒覆盖，退 3；缺目录退 2）。六要素逐份回执、去向分档、`received[]` 回填仍为人工步骤。测试 `tests/intake-check.test.mjs` **5/5**（含四类旗标负控与会红断言）；仓库回归 **567/565/2/0**。使用：`node skill-lifecycle/control/intake-check.mjs --batch trial-home/intake/<BATCH-ID> [--apply]`。

## 4. 边界与下一步

- 本组件只建流程与模板；**未接收任何材料**（`received[]` 全空）。
- 用户可按批提供材料（原始完整包＋简短说明即可）；每批产出回执并回填台账。
- 与 W5 的接口：材料进入"制作候选"后，新技能按既有评估链（含 T1 离线冒烟）验证；如需运行验证走 118 号分档（T1/T2 各自纪律）。
