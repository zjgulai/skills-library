# 60｜探针 B 空跑作废 + 一条装载阻断规则（技能名必须 kebab-case）

**本轮真实请求 126 次 / 96,415 tokens**（硬停 280/1.6M 内）。**24 条记录全部作废**——
不是模型的问题，是**我的执行器有两处缺陷**，读数无意义。作废原因与随之发现的规则一起登记如下。

## 1. 作废原因（两处，都是实现缺陷）

| # | 缺陷 | 证据 | 后果 |
| --- | --- | --- | --- |
| 1 | **任务文本没传进去** | 报告原文写着「业务请求：未提供有效业务请求（显示为 `undefined`）」 | 探针 B 的 `tasks.json` 只写了 `material`/`planted`，**没有 `text` 字段**（探针 A 有）；提示里的 `${text}` 变成 `undefined`，模型只好自己编 |
| 2 | **armed 臂没装上技能** | 会话事件流里 `Skill评估师` 出现 **0 次**；模型猜着调 `skill_evaluation` / `review`，全部被 `SKILL_NOT_ALLOWED` 拒 | 见 §2——对象技能的名字**根本进不了 DSH 的目录** |

**附带修正（含一次我自己的错判）**：探针 B 的"目录门禁"原本用 `hasEvaluator`（在请求文本里找技能名）判定，
而 capture 里那个 `true` 其实来自**被脚本化加载后的技能正文**（不是目录）⇒ 那条门禁是**假绿**。
我随后一度记成"目录在 `request.tools`"——**那也是错的**：实测落盘请求后看清，
目录在 **`messages` 里的 `<system-reminder>`**（`<available_skills>` 开头的技能清单）。
门禁口径已改成 `hasCatalogBlock`（找 `<available_skills>`）＋ `listsSkill`（找技能名），并在 capture 里两臂都验过：
armed 有目录且列出技能、none 都没有。

## 2. 发现的规则：DSH 只认 kebab-case ASCII 的技能名

**源码两处为证**（应用包 `0.1.5-rc.2`）：

- `dsh-skill/lib/index.js`：`const SKILL_NAME = /^[a-z0-9]+(?:-[a-z0-9]+)*$/`，
  `validateCandidate` 对不合规名直接抛 `invalid skill name`；
- `dsh-skill-filesystem/lib/index.js`：
  `if (!isSkillName(name)) { ctx.logger.warn("skill file … ignored: invalid skill name"); return; }`
  ⇒ **逐份忽略**（不是整根报错）——那一份技能在 DSH 里等于不存在，其余技能照常加载。

**回归测试**：`tests/dsh-skill-name-rule.test.mjs`——同一根里放 `kebab-ok` 与 `Skill评估师`，
断言只有前者出现在 `skills.list()`、并留下 `invalid skill name` 警告。
**变异验证**：把中文名换成 kebab 名后测试**当场变红**（证明判据确实挂在名字规则上）。

## 3. 影响范围（全库零请求扫描）

屏检新增 `NON_KEBAB_NAME`（high，措辞写明"DSH 会忽略该技能"），复跑读数：

| 读数 | 加规则前 | 加规则后 |
| --- | ---: | ---: |
| high | 17 | **146**（+129） |
| `NON_KEBAB_NAME` | — | **129** |

分布：**`81-Skills` 81 份（整个包都是中文名）**、`MuseAI-Skills-main` 43 份（`artifact_document` 这类下划线名）、
`paper_to_skills` 5 份。⇒ **全库 734 份里 129 份（17.6%）在 DSH 里是隐形的。**

**这不是新问题**：你自己的 `dsh-overseas-skills` 计划 §3 兼容表第 1 行早就写着
「`name:` 为中文 → 映射英文 kebab 名（§4 表）」——本轮把它**从一句计划变成了可扫、可测、可回归的规则**，
并第一次给出了全库口径。也顺带修正我此前的一处判断：51 号里我把"86 个中文名"记成**风格选择**
（当时看的是"目录与 name 是否一致"），**就 DSH 装载而言它是阻断项**——两条口径不是一回事，之前那条只对了一半。

## 4. 对探针 B 的处置

- 24 条记录与读数**全部作废**（证据仍留在 `trial-home/evidence/probe-b-2026-09-28/`，标为 void）；
- 重跑要改三处：① `tasks.json` 补 `text`（每题一句业务请求）；② 提示里**列出实际 fileId**；

  （记录里同时登记库内原件摘要与安装形态摘要，映射关系留痕）；
- 已花的 126 请求 / 96k tokens 计入本探针额度；重跑约再需 130 请求 —— **合计仍低于 280/1.6M 的硬停**，
  但要不要现在就重跑，等用户点头（见 §6 号文档与 D66）。
