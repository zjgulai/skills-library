# 24｜独立盲判（2026-09-27）

用户 2026-09-27 选择「先做独立盲判」。本步为纯工程 + 一次真实盲判派发，**零新增真实请求**（判者只读产物文本，不调用 DSH 路由）。

## 1. 为什么需要它（记录在案的缺口）

此前所有业务判定都由**主代理**完成，而材料、rubric 与判定出自同一手（自证风险，A4 记录第 7.1 节、20 号复盘第 4 节均登记过）。04 号评测契约要求"裁判自身先验收"与"裁判可以组合、必须给出证据"。本步把判定拆成**可盲、可复算、可解盲**的三段。

## 2. 机制（`control/blind-packet.mjs`）

- **盲包（judge-facing）**：`buildPacket()` 把 W2 形状的逐题记录收敛成 `{slot, taskId, request, criteria, artifact}`，**只带产物正文**；臂名、重复序号、候选 id、尝试数、tokens、技能摘要全部不进盲包。slot 顺序由 `seed` 决定（`sha256(seed:arm:task:repeat)` 排序），**行序不泄露归属**。
- **判据（gold-free）**：每个 taskId 一条预先写死的判据问句（`trial-home/a4/blind-criteria.json`），**不含金标数字与缺陷清单**——例如 t2 只问"是否做了独立复算并指出与数据不符"，不给 5,880／588。
- **键（key-facing）**：`slot → {arm,taskId,repeat,artifactDigest}` 落在 `<packet-dir>/keys/<packetId>.key.json`；写包时**同目录不覆盖**（`PACKET_EXISTS`），`packetDigest` 绑定所寄出的产物摘要。
- **打分与解盲**：`scorePacket()` 要求**每个 slot 恰好一个判定**（缺一 `MISSING_SLOTS`、多余 `UNKNOWN_SLOT`、重复 `DUPLICATE_SLOT`、类型错 `INVALID_VERDICT`）；`unblind()` 把判定映射回臂，并**从原始记录**取 attempts／tokens／incomplete——成本数据全程不进判者视野。
- **泄漏检查**：`leaks(packet, tokens)` 断言盲包里不出现 `candidate`／`original`／候选 id／`attempts`／`tokens` 等字样。
- **CLI**：`blind.mjs prepare <evidence-dir> --out <dir> --seed <s>` / `blind.mjs score <evidence-dir> --packet <dir> --verdicts <file> --round N [--write]`（退出码 0 = accept）。

测试：`tests/blind-packet.test.mjs` 9 项（泄漏检查、按 seed 重排、任务筛选、判定的完备性校验、解盲还原、记录缺失即拒、摘要绑定防篡改、写包与拒绝覆盖、输入校验）。

## 4. 诚实边界（本次盲判做到什么、没做到什么）

1. **隔离是提示级的，不是强制的**：判者被要求只读盲包、且被明确禁止打开 `keys/`，但它的运行环境并未被剥夺文件系统读权限——"不能偷看"靠的是指令与盲包自足性，不是沙箱。（04 号契约要求的"终测答案隔离"仍未实现：我们没有终测集。）
2. **判者与产出同一模型族**：独立上下文不等于独立模型；"经校准的模型裁判"这一点没有做校准集验证。
3. **它验证的是"判定可独立复现"，不是"技能优劣"**：盲判复现了对 W2 这批产物的判定；样本量、模型、路由的边界与 W2 相同。
4. **判据措辞暴露出一处歧义**：判者对 entry-04（候选 t7 r1）标注——"若把判据第二半理解为『有限帮助须真交付』，这条会翻成 false"。**下一轮把该语义在 `blind-criteria.json` 里写死**（是"声明可用"还是"必须实际交付"），否则同一批产物可能因措辞理解不同而翻判。
5. **判者质量本身需要被验收**：本次判者的 10 条判定与机械门 100% 一致，说明它至少没有系统性跑偏；但"只会同意"的判者也会拿到 100%——后续应加入**反向探针**（在盲包里混入一条已知不合格的产物，看判者是否敢判 false），本次未做。
